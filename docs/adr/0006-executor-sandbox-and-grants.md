# 执行器：目录沙箱 + 工具白名单 + run 级授权

需求草稿要求「直接交给本机上终端完全权限的 agent」的那个按钮，实质是任意代码执行：一次误分类就可能让 agent 在工作站上做任何事。因此每个 `WorkflowRun` 拿到独立工作目录、一份显式工具/命令白名单、一份读白名单（哪些 `Corpus` 可读）；凭证不进 agent，由宿主代理调用；授权是 run 级的、可撤销，并留下审计日志。

**Considered Options**

- **完全权限（就是你的用户权限）**：最灵活，但误分类等于不可逆损失，且无可审计边界。
- **每次执行前人工确认**：最安全，但取消了那个按钮的意义。
- **目录沙箱 + 白名单 + run 级授权**（选定）：兼顾「不用再对齐直接做」与可撤销、可审计。

**Consequences**

- 「回滚这次 run」必须有明确定义：run 工作目录可整体丢弃，但已经发生的外部副作用要能被审计出来。
- 交接方式是 `ExecutorJob` 文件 + 监听目录的拉取模型，不是推送——Pi v0.80.7 没有 RPC 与 server 模式（见 ADR-0003）。
- 高置信自动跑的闸门（ADR-0005）与这里直接相关：阈值不准时，沙箱是唯一的兜底。
